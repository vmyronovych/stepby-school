# StepBy School

Освітній портал українською. Цей файл містить тільки спільні правила та маршрути до локальних інструкцій.

## Порядок читання

1. Прочитай цей файл.
2. Визнач курс і прочитай його `CLAUDE.md` **до редагування**, навіть якщо інструмент не завантажив його автоматично.
3. Прочитай локальні правила заняття, якщо вони існують. Застосовуй лише потрібний скіл із каталогу курсу.
4. Працюючи над спільною частиною, перевір усі курси, яких торкається зміна.

Для українських навчальних матеріалів, інтерфейсу й документації застосовуй спільний скіл [ukrainian-language](.agents/skills/ukrainian-language/SKILL.md). Не копіюй його в папки курсів.

## Спільні обмеження

- React, strict TypeScript, явні ES-імпорти. Зберігай типи біля відповідної реалізації. Без циклів, прихованої реєстрації й неперевірених приведень типів.
- Кореневий `index.html` — шаблон. Готовий `dist/index.html` завантажує локальний IIFE `dist/assets/app.js` за відносною адресою `assets/app.js`. Підтримуй `file://`, GitHub Pages та офлайн. Без CDN, бекенду чи `type="module"` у стартовому HTML.
- Навчальний стан живе в пам’яті. Не використовуй `localStorage` чи `sessionStorage`.
- React керує інтерактивним UI та життєвим циклом. `LegacyHtml` — тільки для довіреного навчального тексту й статичних ілюстрацій. Слухачі, звук, таймери й анімація мають очищатися після демонтування.
- UI українською; бренд — `StepBy School`. Назви предметів бери з даних. Не змінюй ідентифікатори класів, тем та завдань при перейменуванні.
- Для переходів використовуй `<a href>` і функції hash-навігації. Зберігай прямі посилання, історію та поведінку «Назад» / «Вперед».
- Один власник кожного джерела: заняття → курс → спільна частина. Курси не імпортують внутрішні файли інших курсів. Зовнішній код використовує лише задокументовані публічні входи.
- Спільний код не імпортує реалізації занять. Збирання курсів дозволене в шарі композиції застосунку. Не створюй спільні абстракції без реальних користувачів.
- Стилі курсу обмежені його селекторами. Загальні стилі, токени та механізми документів не належать окремому курсу.
- `dist/` — єдиний результат збірки, виключений із Git. Коміть вихідні файли й канонічні навчальні матеріали; не створюй кореневий `assets/` і не коміть результати збірки. Сайт публікується з перевіреного артефакту GitHub Actions.
- `esc()` не екранує одинарну лапку: використовуй його тільки в атрибутах із подвійними лапками.

## Команди та перевірка

- `npm ci` — залежності; `npm run dev` — локальний сервер зі стеженням за змінами.
- `npm run build` — чиста збірка всього сайту в `dist/`: типи, HTML, стилі, матеріали курсів, IIFE.
- `npm run preview` — показ наявного `dist/` без перебудови.
- `npm test` — збірка, загальні й локальні тести курсів; `npm run test:browser` — браузерні перевірки всіх курсів.
- `npm run check:architecture` — залежності та цикли.
- Перед завершенням змін виконай збірку, модульні й браузерні перевірки та `git diff --check`. Перевір console/pageerror, змінені екрани та `file://`.
- Для анімацій перевір послідовність, переходи між кроками та `prefers-reduced-motion`; для інструментів — збереження стану й очищення ресурсів.
- Форматуй змінені TS/TSX. Не форматуй весь репозиторій заради локальної правки.

Спілкуйся прямо й по суті. Сумнівні рішення пояснюй до реалізації. Не скасовуй чужі незавершені зміни.

Залишай зміни локально. Виконуй `git push` лише на окреме явне прохання користувача. Попередній дозвіл відкрити або оновити PR не означає дозволу пушити кожну наступну правку. Автоматичні перевірки й публікація запускаються лише після push у `main`; перед злиттям PR виконай перевірки локально.

Перше перемикання GitHub Pages з публікації гілки на Actions описане в [docs/deployment.md](docs/deployment.md). Не змінюй живе налаштування публікації побіжно під час локальної роботи.
