# StepBy School

Освітній портал українською. Цей файл містить тільки спільні правила та маршрути до локальних інструкцій.

## Порядок читання

1. Прочитай цей файл.
2. Визнач курс і прочитай його `CLAUDE.md` **до редагування**, навіть якщо інструмент не завантажив його автоматично.
3. Прочитай локальні правила заняття, якщо вони існують. Застосовуй лише потрібний скіл із каталогу курсу.
4. Працюючи над спільною частиною, перевір усі курси, яких торкається зміна.

Для українських навчальних матеріалів, інтерфейсу й документації застосовуй спільний скіл [ukrainian-language](.agents/skills/ukrainian-language/SKILL.md). Не копіюй його в папки курсів.

## Власність коду

- `src/courses/<курс>/` — навчальний зміст, інструменти, стилі, ресурси, генератори, тести й правила конкретного курсу.
- `src/components/<модуль>/` — самодостатні спільні модулі. Вони отримують дані та дії через параметри й не імпортують курси, каталог або `app`.
- `src/app/` — екрани порталу та композиція: підключення курсів, документів і спільних модулів. Загальний каталог екранів знаходиться в `app/catalog/`.
- Підключення курсів і початкова реєстрація належать `app/composition.ts`; `runtime/` не імпортує `app` або курси. Курс надає повні переліки своїх інструментів і форм. У `app` не визначай початкові значення, приклади або підказки окремих уроків.
- Курс визначає свої режими сторінки, навігацію, інтерактивний вміст документа й особливості адрес. `App.tsx` і спільні компоненти отримують готові налаштування; не перевіряють назви курсів або ідентифікатори їхніх матеріалів. Підключай такі налаштування через окремі реєстри композиції.
- `app/catalog/registry.ts` задає лише порядок готових курсів. Кожен курс через `index.ts` надає об’єкт `Course` з власними `subject` і `topics`; `app/catalog/catalog.ts` автоматично збирає з них загальний каталог. Не додавай ручних переліків уроків до реєстру. Підключення налаштувань адрес належить `navigation/course-registry.ts`. Метадані залишаються в курсах. Не створюй для коду підключення окрему папку `data`. Математичне ядро, `runtime` і навігація не імпортують `app`; потрібні дані й функції передає застосунок.
- Каталог містить наявні курси, уроки та інструменти. Не повертай довідник `classes`, штучні класи курсів, вигаданих користувачів або ознаки майбутніх предметів. Групи уроків визначає `Topic.grades`; поля `cls` зберігають адреси й не визначають групування.
- Папку `src/features/` видалено. Не створюй її знову й не вводь паралельну папку для коду з тими самими відповідальностями.
- Курси не імпортують глобальний каталог або `app`. Метадані свого уроку бери з його власного файла; дані застосунку передавай через параметри.
- `lib/` містить незалежні бібліотеки зі зрозумілим призначенням. Кожна має власну папку й публічний вхід; випадкові допоміжні функції залишай біля коду, який їх використовує.
- `lib/math/` містить лише обчислення й розбір виразів. Показ формул, рівнянь, числової прямої та стовпчиків належить `components/notebook/rendering`. Визначення інструмента — `runtime/tool.ts`, його реєстрація — `app/tools/register.ts`.
- Спільні низькорівневі області (`navigation`, `runtime`, `lib/math`, типи) зберігають своє призначення. Не перенось їх до UI-компонентів лише заради уніфікації назв.

Нові модулі курсів організовуй за зразком `src/courses/robotics/`. Докладніше: [структура й залежності](docs/course-structure.md), [наявна архітектура](docs/application-architecture.md).

## Спільні обмеження

- React, strict TypeScript, явні ES-імпорти. Зберігай типи біля відповідної реалізації. Без циклів, прихованої реєстрації й неперевірених приведень типів.
- Кореневий `index.html` — шаблон. Готовий `dist/index.html` завантажує локальний IIFE `dist/assets/app.js` за відносною адресою `assets/app.js`. Підтримуй `file://`, GitHub Pages та офлайн. Без CDN, бекенду чи `type="module"` у стартовому HTML.
- Навчальний стан живе в пам’яті. Не використовуй `localStorage` чи `sessionStorage`.
- React керує інтерактивним UI та життєвим циклом. `LegacyHtml` — тільки для довіреного навчального тексту й статичних ілюстрацій. Слухачі, звук, таймери й анімація мають очищатися після демонтування.
- UI українською; бренд — `StepBy School`. Назви предметів бери з даних. Не змінюй ідентифікатори класів, тем та завдань при перейменуванні.
- Для переходів використовуй `<a href>` і функції hash-навігації. Зберігай прямі посилання, історію та поведінку «Назад» / «Вперед».
- Один власник кожного джерела: заняття → курс → спільна частина. Курси не імпортують внутрішні файли інших курсів. Зовнішній код використовує лише задокументовані публічні входи.
- Спільний код не імпортує реалізації занять. Збирання курсів дозволене в шарі композиції застосунку. Не створюй спільні абстракції без реальних користувачів.
- Стилі курсу обмежені його селекторами. Загальні стилі, токени та механізми документів не належать окремому курсу.
- `dist/` — єдиний результат збірки, виключений із Git. Коміть вихідні файли й канонічні навчальні матеріали; не створюй кореневий `assets/` і не коміть результати збірки. Сайт публікується з перевіреного артефакту GitHub Actions.
- `esc()` не екранує одинарну лапку: використовуй його тільки в атрибутах із подвійними лапками.

## Команди та перевірка

- `npm ci` — залежності; `npm run dev` — локальний сервер зі стеженням за змінами.
- `npm run build` — чиста збірка всього сайту в `dist/`: типи, HTML, стилі, матеріали курсів, IIFE.
- `npm run preview` — показ наявного `dist/` без перебудови.
- `npm test` — збірка, загальні й локальні тести курсів; `npm run test:browser` — браузерні перевірки всіх курсів.
- `npm run check:architecture` — залежності та цикли.
- Перед завершенням змін виконай збірку, модульні й браузерні перевірки та `git diff --check`. Перевір console/pageerror, змінені екрани та `file://`.
- Для анімацій перевір послідовність, переходи між кроками та `prefers-reduced-motion`; для інструментів — збереження стану й очищення ресурсів.
- Форматуй змінені TS/TSX. Не форматуй весь репозиторій заради локальної правки.

Якщо знімок або відкрита вкладка відрізняються від локального результату, перевір актуальність збірки й кеш перед повторною зміною стилів чи маршрутизатора. Перевіряй проблемні посилання і через HTTP, і через `file://`.

Спілкуйся прямо й по суті. Сумнівні рішення пояснюй до реалізації. Не скасовуй чужі незавершені зміни.

Коміт створюй на окремий запит користувача; не додавай атрибуцію ШІ до повідомлення коміту.

Перед кожним `git push` обов’язково прочитай і виконай [push-changes](.agents/skills/push-changes/SKILL.md).

Налаштування GitHub Pages і публікація через Actions описані в [docs/deployment.md](docs/deployment.md). Не змінюй живе налаштування публікації побіжно під час локальної роботи.
