# StepBy School

Освітній портал українською для всіх шкільних предметів і гуртків — **крок за кроком**. Зараз є математика (5–6 і 10 кл.), інформатика (3–4 кл.) і гурток робототехніки (3–4 кл.); інші предмети в розробці. Інструменти для учня пояснюють розв'язання, малюючи його на зошиті в клітинку так, ніби учень пише від руки. Головна цінність покрокових інструментів — саме ця анімація; більшість правил нижче про неї.

**Як читати цей файл.** «Стек» і «Архітектура» — як усе влаштовано й де що лежить. «Як інструмент пише й пояснює» та «Обчислення в стовпчик» — вимоги до анімації, це головне. «Конвенції» — дрібні правила коду. «Інформатика 3–4» — вимоги до КТП і конспектів для вчителя.

Крім покрокових інструментів у порталі є матеріали для вчителя: гурток робототехніки (3–4 кл.) і **інформатика 3–4 класів НУШ** — КТП на 2026/2027, конспекти уроків і схеми на проєктор (див. розділ «Інформатика 3–4»). Портал — єдине джерело цих матеріалів; окремий сайт `uroky-informatyky` і його копія-артефакт на claude.ai більше не ведуться.

## Стек і як запускати

- React + strict TypeScript керують усім UI. Встановлення: `npm ci`. Розробка: `npm run dev`.
- `npm run build` перевіряє типи та створює локальний IIFE-бандл `assets/app.js`.
- `index.html` завантажує один звичайний скрипт. Працюють `file://`, GitHub Pages та офлайн-режим.
- ES-модулі використовуй у `src/`. Не додавай CDN, бекенд чи `type="module"` у `index.html`.
- Не використовуй `localStorage` або `sessionStorage`. Навчальний стан живе в пам'яті.
- UI розкладай за функціями: `src/features/<feature>/`. Спільні примітиви — `src/components/`.
- Передавай типізовані props. Компоненти не читають браузерні глобальні змінні.
- Форматуй TSX перед review. Коміть `assets/` разом зі змінами джерел.

### Перевірка змін

1. Запусти `npm run build`, `npm test` та `npm run test:browser`.
2. Перевір помилки консолі й `pageerror`; знімки зошита та змінених панелей.
3. Перевір послідовне письмо, польоти, стрибки між кроками та `prefers-reduced-motion`.
4. Для маршрутів перевір прямі URL, «Назад»/«Вперед», власну умову та `file://`.
5. Для проєкторів перевір керування, зміну пресета без скидання та зняття слухачів після виходу.
6. Після збірки перевір `git diff --check` і відповідність `assets/` джерелам.

API для браузерних перевірок: `StepBySchool.navigate(href)`, `changeStep(index)`,
`getSnapshot()`, `getCatalog()`, `getToolDefinition()`. Сам UI імпортує модулі,
а не використовує цей браузерний API.

## Архітектура

- `catalog` містить дані. Двигуни реєструють 16 інструментів через `registerTool`.
- `src/app/controller.ts` керує маршрутом, умовою, моделлю, кроком та історією прокрутки.
- React читає незмінні знімки через `useSyncExternalStore`; публікація кроку синхронна для вимірювань анімації.
- Приватне `engineState` лише дає старим математичним функціям поточний контекст; це не браузерна глобальна змінна.
- React керує всіма оболонками, формами, проєкторами та їхнім життєвим циклом.
- Двигуни лишаються JavaScript для математики, SVG, фізики та файлових операцій.
- `LegacyHtml` допускає текст уроків і графіку. Не створюй через нього новий інтерактивний UI.
- Старі `js/app.js`, `js/data.js`, `js/ui/` та глобальні UI-функції видалено.
- Від'єднані прототипи кабінетів вчителя й адміністратора не мали маршрутів і не входять до застосунку.

### Матеріали-документи

Розділ містить `title`, `html` та необов'язкове `app`.
Текст і статичні SVG — довірені навчальні матеріали, які не треба переписувати на JSX.
`DocumentPage` керує змістом, фігурами, друком, редагованими полями та переходами до якорів.
`ContentSlot` монтує React-проєктор у виділене місце статті, зберігаючи посилання на конспекти.
Геометрія, клавіатура, Windows та панель кола мають власні feature-компоненти.
Для окремих матеріалів дозволено `init`/`onSub`/`leave` як межу спеціалізованого двигуна.
Кожен глобальний слухач або таймер має явне очищення при демонтуванні.

### Конструктор електричного кола (гурток робототехніки)

Вільна інтерактивна пісочниця для проєктора (`js/robo/circuit/`), а не покроковий інструмент,
тому він **поза реєстром**. Це розділ `sim`. `CircuitProjector` монтує SVG-двигун і прибирає
його rAF, слухачі перетягування, клавіші та звук при демонтуванні.

**Деталі.** Кожна деталь — запис у `CIRC.parts` (контракт — у шапці `parts.js`). Нова дводротова
деталь сама з'являється в панелі й у вікні властивостей. Але в кількох деталей є поведінка за типом
у `sim.js` / `breadboard.js`: батарейка (живлення, вимикач MB102), світлодіод, зумер (звук),
кнопка й вимикач — нова деталь такого роду потребує правки й там.

**Струми й електрони.**
- Струми рахує справжній розв'язувач (`solveCircuit`), тож перегрів і коротке замикання — наслідок
  струму, а не окремі правила.
- Дроти завжди повні електронів. Електрони — **один ланцюжок на все коло**: `chain()` вирівнює
  фази провідників за течією, тож на стиках крапка не зникає.
- Кімнати батарейки тануть рівно за потоком (`drain`), а доріжки-`ramps` усередині батарейки
  показують, як електрон виходить і заходить.

**Інтерфейс — пряма робота зі схемою.** Панель деталей, дроти й вікно властивостей (подвійний клік
або права кнопка, поле `params`). Над полем — лише перемикач «Схема / Макетка», швидкість,
«Скасувати» / «Повернути» й «Очистити поле». **Кнопок-режимів (на кшталт «Увімкнути живлення») і
кнопок із готовими колами немає**: усе, зокрема коротке замикання, збирається на схемі. На старті
на полі вже зібране перше коло із заняття 1.

**Правка — як у звичних редакторах схем:**
- вільна деталь, кинута на дріт, розрізає його (`cbInsert`);
- «Вийняти з кола» (або Alt + перетягування), вирізання й видалення з'єднують сусідів напряму
  (`cbExtract`) — коло не рветься;
- дріт — перетягуванням або «клік — клік»; кінець вибраного дроту можна перечепити;
- рамка й Shift — виділення; стрілки — зсув (Shift — на 3 клітинки); R — поворот;
- Ctrl + Z (з Shift — повернути) / Y / X / C / V / D / A, Delete, Esc — за `event.code`, тож
  працює на обох розкладках;
- скасування — знімки `cbSnap` у `ROBO.circuit.undo`, до 100 кроків; стан деталей (згорів, заряд)
  не відкочується.

**Макетка.** Вигляд «Макетка» (плата 830) — те саме коло, а не окреме, і правиться в обох виглядах.
- Схема й макетка — два записи тих самих з'єднань: `B.wires` і `B.bb` (`B` — це `ROBO.circuit`;
  `place` — ніжки деталей в отворах, `jumps` — перемички).
- Правка на макетці → `cbSchemFromBoard` переписує дроти схеми (мінімально); правка на схемі →
  `cbBoardFromSchem` лагодить розкладку, не рухаючи того, що стоїть правильно.
- `cbBreadboard(B)` дає дроти макетки (ніжки, смужки, шини, перемички), які рахує той самий
  `solveCircuit`. Прибрана з макетки деталь лишає перемичку, якщо в обох її смужках є інші деталі.
- На макетці інакше, ніж на схемі: немає «Вийняти з кола» й рамки; живлення не прибирається й
  не рухається; стрілки зсувають на один отвір, R перевертає ніжки. Деталь, що не вмістилась,
  «лежить під платою» і тримає з'єднання схеми.
- Обраний вигляд живе в `ROBO.cbView` (за замовчуванням — схема).

**Живлення** (`battery`) має властивість `src`:
- `mb` (за замовчуванням) — павербанк через модуль MB102, 5 В / 3,3 В, як на гуртку. На макетці
  модуль стоїть на лівому краї й живить обидві пари шин, біла кнопка вмикає його. Коротке
  замикання вимикає захист павербанка.
- `aa` — пальчикові батарейки, встромлені у верхні шини. Від короткого замикання батарейка
  здувається й тече.
- Куди встромлене живлення — `bbLeads(B)`.

### Реєстр і нові інструменти

Математичний контракт у `js/core/registry.js`: `name`, `icon`, `color`, `bg`,
`build(config)`, `view(model, context)` і `read(readField)`. Анімація додає `prepare` та `animate`.
Некоректна умова кидає рядок-пояснення; `'bad'` показує `errorHint`.
HTML-шаблони форм і від'єднаних редакторів видалено. Поля створює React у `features/tools/inputs/`.

Життєвий цикл: `changeStep` → `prepare` зі старого DOM → синхронний React commit →
два rAF → `animate`. У зменшеному русі `prepare` не викликається.
Хук скасовує відкладені кадри при переході або демонтуванні.
`view` має показувати готовий крок, коли `context.anim` порожній.

Новий інструмент:

1. Додай модель до `js/tools/` та реєстрацію через `registerTool`.
2. Додай джерело в `scripts/engine-runtime.mjs` у порядку його залежностей.
3. Додай React-поля до `src/features/tools/inputs/ToolInputs.tsx`.
4. Додай завдання до `src/data/catalog.ts` і перевірки моделі та UI.
5. Збережи спільні формули, зошит і послідовну анімацію.

## Як інструмент пише й пояснює (головне в проєкті)

**Золоте правило — писати як людина.** Кожна поява — у тому порядку й темпі, як людина писала б від руки, спокійно пояснюючи: **≈0.34 с на штрих/елемент** (`HW_DUR`, такт між гліфами — `HW_STEP`). Ніколи не анімуй паралельно те, що пишеться одне за одним — **строга послідовність** (кожен елемент приземлився → тоді наступний). Поважай `prefers-reduced-motion` (показати фінал без руху). Фінальні відповіді — **зеленим**.

**Зошит у клітинку.** Рендер на сітці: світло-блакитна клітинка ≈30px, цифри ≈19–22px. Аркуш — герой сторінки, панель умови — вузька й компактна. У стовпчик кожна цифра у своїй клітинці, лінії — по лініях сітки.

**Рукописне письмо.** Цифри/знаки не «зʼявляються», а **малюються пером**: SVG одним штрихом через `stroke-dashoffset` (див. мапу гліфів `HW` і `hwGlyphs`). Порядок штрихів — зліва направо, зверху вниз. Нічого зі спільної секції не має **зникати** — запис накопичується.

**Навичку з іншого уроку не пояснюємо заново — посилаємось на урок.** Якщо крок інструмента — окрема тема порталу (розклад на прості множники в НСК і НСД, …):
- у тексті кроку — лише результат, без докладного розбору;
- на полях аркуша, праворуч від цього запису, — нотатка з посиланням на той урок: `lessonNote(toolId, 'Як …', anim)`;
- урок знаходить `topicForTool(toolId)` (тема з завданнями цього інструмента, спершу в поточному класі) — id теми не хардкодь;
- нотатка з'являється разом із першим таким записом (такт пера `hwfade`) і лишається до кінця.

Новий інструмент, що спирається на вже наявний, робить так одразу — не чекай, поки про це нагадають.

**Один рядок = один крок; попередні рядки лишаються видимими** (рівняння, дроби). У межах рядка: спершу `=`, тоді доданки зліва направо. Дріб пишеться послідовно: чисельник → риска (малюється) → знаменник → операція → наступний дріб.

**Перенос через `=` (рівняння):** доданок летить **разом зі своїм знаком** зі старого місця на нове; знак **міняється в момент приземлення** (він перетнув `=`). Строго по черзі.

**Зведення/обчислення (combine):** доданки летять і **сходяться** в точку результату, де він і зʼявляється. Для додавання чисельників дробів лети **одним написом** `21 + 4`, що згортається в суму; **оригінали не зникають**, спільний знаменник **зноситься одним рухом** (його не додають).

**Спільний знаменник у дробах (`frac`) — найважче, тож навчай покроково.** Тут НСК шукаємо переліком кратних (а не розкладом, як в інструменті `nsk`). По черзі відкривай наступне кратне першого знаменника, тоді другого, **звіряючи після кожного**; перший збіг = НСК. Індекс, на якому стоїть НСК, — це множник дробу; множники `·k` — окремим кольором, і вони **влітають** із чипів НСК у дроби (чисельник₁ → знаменник₁ → чисельник₂ → знаменник₂), по черзі.

**FLIP (реалізація польотів):** джерела лишаються на екрані, тож позиції читай з **живого DOM після рендера**. Клон отримує **той самий padding**, що й оригінал (інакше зсув = «каша»); ціль спершу схована, розкривається на прильоті. Для морфінгу (джерело стає іншим результатом) — ховай джерело на час польоту. Розводь польоти затримками, щоб кожен завершився до наступного.

### Антипатерни (кожен був реальною скаргою — уникай)

- Великі цифри + малий аркуш (вміщається лише один крок у рядок).
- Сірі підказки **всередині** виразу — вони мають бути **під** сегментом.
- Поява всього одразу замість штрих за штрихом; паралельні польоти замість послідовних.
- Клони летять поверх видимих оригіналів або без вирівнювання padding → двоїння/«каша».
- Секція зникає між кроками (напр. дільники зникли, коли додались кратні) — запис має **накопичуватись**.
- Додавання спільного знаменника (30 + 30) замість знесення одним рухом.
- Стовпчиком: результат записується цілим числом, та ще й зліва направо, замість розбору цифра за цифрою.
- Результат з'являється разом із питанням: учень не встигає прочитати підказку й подумати сам.
- Порожні рядки «про запас» у стовпчику (під число в умі) — зошит так не виглядає.

## Обчислення в стовпчик (додавання, віднімання, множення, ділення)

Усі стовпчикові інструменти стоять на одному ядрі `js/core/column.js`. Інструмент лише будує план
і на кожен крок кличе `sheet.snap({news, hl, op, phase, …})`. Рендер, такти пера, польоти і
«спокійний режим» — у ядрі. Новий стовпчиковий інструмент — тонкий адаптер над ним, а не копія.

### Загальні правила

1. **Одна дія — один розбір, від одиниць справа наліво.** Ніколи не записуємо результат цілим числом.
2. **Кожна дія — три кроки «Далі»**, між ними зупинка, щоб учень прочитав підказку й подумав сам:
   - `q` — питання: праворуч від стовпчика пером пишеться лише вираз `6×4=`;
   - `a` — відповідь: дописується `24` і підпис у дужках `(4 — записуємо, 2 — запам'ятовуємо)`;
   - `fly` — цифри з чернетки летять на свої місця в стовпчику.
   Винятки: коли рахувати нічого (цифру просто зносимо) — один крок без чернетки; коли нічого
   не летить у стовпчик — лише `q` і `a` (остача 0 посередині ділення, нуль на початку різниці);
   неповне ділене 0 не зноситься польотом («Маємо 0 — його не пишемо»).
3. **Чернетка** — праворуч від стовпчика (через одну клітинку), у рядку, куди піде цифра. Якщо до
   результату треба ще щось додати чи відняти, це другий рядок чернетки: `6×8=48`, під ним `48+2=50`.
   Чернетка живе лише свою дію, після польоту лишається до кінця кроку.
4. **Кольори:** у чернетці вираз сірий, те, що «в умі», — жовте, цифра, що йде в стовпчик, — темна.
   Підсвітка `hl` (тло) — цифри, з якими зараз працюємо. Відповідь — зелена.
5. **Польоти, а не поява.** Цифра відповіді летить із чернетки на своє місце; число «в умі» летить
   угору й на льоту зменшується. Спершу цифра в стовпчик, тоді число «в умі» — строго по черзі.
   Джерело польоту лишається на місці.
6. **Число «в умі» й позначка «позичили» (крапка) — дрібно в правому верхньому куті клітинки**
   з цифрою, до якої їх застосують (`colGrid`, поле `sup`). Окремих рядків під них немає.
   Стани: жовте — поки в умі; жовте тло — коли саме його використовуємо; сіре — використане.
7. **Знак дії** (`+ − × `) — по вертикалі посередині між двома операндами (на лінії сітки, клас `mid`),
   по горизонталі — на клітинку лівіше за довший операнд. Зліва стовпчика завжди є вільний стовпець.
8. **Стовпчик щільний, як у зошиті**: жодних порожніх рядків «про запас». Риска — лише під
   стовпчиком, під чернетку не заходить.
9. **Нулі на початку числа не пишемо**; крок це пояснює (`(0 — на початку числа не пишемо)`).
10. **Текст унизу пояснює дію**, а не дублює аркуш: на `q` — що робимо («Множимо 6 на 8, а тоді
    додаємо 2, що в умі»), на `a` — результат, на `fly` — куди що стає.
11. **Фінал:** стовпчик лишається, під ним рядок-відповідь (`284 × 36 = 10224`).
12. **Стрибок через кроки, «Далі» посеред польоту, `prefers-reduced-motion`** — крок видно повністю.
    Ядро будує два варіанти кроку: `html` (усе пише перо) і `htmlFly` (цілі сховані до прильоту);
    `colToolBase` вибирає за `ctx.anim`. Таймери польоту перевіряють, що крок ще на екрані.

### Множення

- Неповні добутки — по одному на кожну ненульову цифру другого множника, зі зсувом під її розряд
  (підказка першого кроку рядка каже, під яким розрядом починаємо). Нуль у другому множнику — рядок
  пропускаємо з поясненням. Нулі в кінці другого множника: якщо неповний добуток один — дописуються
  окремим кроком; якщо кілька — нуль пишеться під час додавання («Цифр немає — пишемо 0»).
- На останній цифрі першого множника результат пишеться повністю (`17`, а не 7 і 1 в умі).
- Число «в умі» — у куті **наступної цифри першого множника**. Коли беремо нову цифру другого
  множника, сірі (використані) числа над першим множником **тануть** — інакше новим немає місця.
  Це свідомий виняток із правила «нічого не зникає».
- Далі неповні добутки додаються тим самим `colAddRun`, що й у додаванні; «+» — між першим і другим.

### Додавання і віднімання

- Додавання: число «в умі» — у куті наступної цифри верхнього доданка (якщо цифри там немає —
  у порожній клітинці). На останньому розряді сума пишеться повністю.
- Віднімання: якщо цифри не вистачає, позичаємо 1 у сусіда зліва — над ним жирна крапка в куті,
  тут маємо на 10 більше (`13−8=`). Цифра з крапкою спершу віддає 1 (`5−1=4`, потім `4−1=`);
  нуль із крапкою сам позичає в сусіда (`10−1=9`). Зменшуване, менше за від'ємник, — помилка умови.

### Ділення («куточком»)

- Дільник праворуч за вертикальною рискою, під ним риска й частка (зелена). Перший крок після
  запису — перше неповне ділене (підсвітка) і скільки цифр буде в частці.
- Для кожної цифри частки три дії, кожна по три кроки: ділимо `72:8=` → цифра летить у частку;
  множимо `9×8=` → «−» і добуток летить під неповне ділене; віднімаємо `72−72=` → остача під риску
  (остача менша за дільник — підказка це проговорює). Потім наступна цифра діленого **летить униз**.
- Неповне ділене менше за дільник → у частку 0, множення й віднімання не пишемо.
  Остачу 0 посередині не пишемо (одразу зносимо); 0 як остачу в кінці — пишемо.

## Конвенції та підводні камені

- **Уся мова інтерфейсу — українська.** Копірайт витриманий, без англіцизмів у видимому тексті. Бренд у шапці — `StepBy School`.
- Заголовки/крихти всередині предмета беруть назву предмета з даних (`subj.name`), не хардкодь «Математика» — інші предмети (українська, фізика, хімія) у розробці.
- **Не міняй `id`** тем/завдань/класів — на них зав'язані посилання; для перейменування класів міняй лише `name`.
- Логотип — посилання на `#/` (єдина верхня навігація, крім крихт). Крихти — `crumbs([{t, href}])` (останній пункт — `{t}` без посилання).
- **Приватні імена двигунів.** Файли `js/` збираються в один приватний модуль. Не дублюй імена його функцій; використовуй `rg` перед додаванням допоміжної функції. UI-компоненти використовують звичайні ES-імпорти.
- `esc()` екранує `& < > "`, але не `'` — у атрибути став його лише в подвійних лапках.
- Порядок тем на сторінці предмета = порядок у масиві `DB.topics`; порядок інструментів на сторінці теми = порядок їхніх завдань у `tasks`. Маніфест двигунів задає лише порядок залежностей, а не порядок карток.
- У рендері інструмента `ctx` — це контекст кроку з реєстру (`{step, index, anim}`), а `pen` (`{writing, order}`) — контекст рукописного пера. Не плутай і не затінюй одне одним. (Усередині `hwEqline` і `colGrid` перо локально теж зветься `ctx` — у коді інструмента так не роби.)

### Схема конспекту

```js
INFO.g3.plans[4] = {
  goal:'мета одним реченням',
  equip:['ПК на кожного учня', 'проєктор'],
  steps:[
    {t:'03–12', d:'9 хв', h:'Заголовок етапу',
     tag:'межа 15 хв',          // необов'язково; тег зі словом «журнал» — рожевий (акцент)
     show:'keyboard:caps',      // необов'язково; посилання на схему на проєктор (+ пресет)
     b:['що робимо', '…'],      // допускається інлайновий HTML
     say:{l:'Скажи класу', t:'«репліка»'}},   // необов'язкова врізка; t теж допускає HTML
  ],
  hw:'Не задаємо.',
};
```
`t` — хвилини уроку «від–до»: з них будується лінійка 45 хв над етапами. Етап, де `d` містить «ПК» або тег «15 хв», — робота за екраном; етап зі словом «очей» у заголовку — гімнастика. Лінійка лише малює — **код не перевіряє жодного з обмежень нижче**, їх звіряєш сам.

### Жорсткі обмеження для будь-якого нового конспекту

1. **Безперервна робота за екраном ≤ 15 хв** — п. 7 Санітарного регламенту (наказ МОЗ № 2205 від 25.09.2020) для 2–4 класів. Практична частина планується на 11–14 хв, не більше. Це не рекомендація.
2. **Урок 45 хв**, сума таймінгів має сходитися рівно.
3. **Гімнастика для очей 2 хв** обов'язкова перед практичною роботою.
4. **Домашніх завдань у початковій школі не задаємо.** `hw` — «Не задаємо» або необов'язкове завдання без перевірки.
5. **Оцінювання вербальне та рівневе**, не бальне. Конспекти не містять виставляння оцінок.
6. ПК на кожного учня (або один на двох), є проєктор.

Типова структура 45 хв: організація 3 → актуалізація 7–10 → нове 10–14 → гімнастика 2 → практична 11–14 → підсумок 6–7.

### Як писати конспекти

Аудиторія — учитель, який читає це з телефона під час уроку. Тому:
- конкретні дії, а не методичні формулювання: «пройди рядами і поправ посадку», а не «здійснити індивідуальний підхід»;
- називати типові помилки дітей до того, як вони стануться, і що казати вголос;
- обмеження в практичних завданнях навмисні (напр. «лише три інструменти») — вони тренують конкретну навичку, не прибирати їх «для свободи творчості»;
- кожен блок практичної закінчується явним збереженням файлу з іменем за схемою `Прізвище_щось`;
- без емодзі, без вигуків, без мотиваційних вставок.

### Схеми на проєктор

Окрема сторінка-тема (`kind:'tool'`, розділ `app:true`). На неї ведуть посилання з етапів конспекту з полем `show`; пресет — в адресі (`#/3a/info/kb3/caps`), кнопки пресетів на схемі міняють адресу через `docReplaceSub`.

- **У якому класі видно схему.** Картку схеми в класі заводять вручну — записом у `DB.topics` (`doc:'inf4-keyboard'` тощо; розділи є для обох класів). Зараз клавіатура — у 3 кл., Windows — у 4 кл., бо саме там їх відкривають конспекти. Якщо конспект посилається на схему, картки якої в його класі немає, посилання веде на сторінку іншого класу. 
  Сторінка схеми сама показує, у яких уроках її відкривають, а на картці з'являються мітки «урок N».
- **Як влаштовано.** React-компоненти `KeyboardProjector` і `WindowsProjector` створюють UI та керують монтуванням. Контролери зберігають текст і файли в пам'яті. Хуки знімають слухачі та таймери при виході; пресет змінюється без скидання стану.

**`keyboard[:пресет]`** — повнорозмірна клавіатура з українськими й англійськими літерами, розфарбована за п'ятьма групами.
- Пресети: `five`, `caps`, `bsdel`, `win`, `alt` або група `let`, `num`, `fn`, `ctl`, `nav`.
- Натискання на клавіатурі ПК учителя підсвічують ту саму клавішу (за `event.code`) і друкуються в полі під схемою. Мову поля показує мітка (УКР / ENG, розпізнає й РУС).
- Поле — власний маленький редактор (`kbTypeKey`), не textarea: товстий курсор і «привид» стертої літери. Працює як Блокнот: стрілки, Home/End, Shift-виділення, Ctrl + стрілки, Ctrl + A/C/X/V/Z, Insert — заміна.

**`windows[:10|11]`** — навчальна копія Windows 10 і 11: на віртуальному екрані лише те, що є в справжній Windows. Надбудови — поза ним або поверх: «Показувати клавіші» (натиснуті комбінації поверх екрана, увімкнено за замовчуванням), «Крупніше», «Скинути» (повертає початковий стан).
- Робочий стіл із теками класів: 3А, 4А, 5А–7А на столі; 3Б, 4Б, 8А–11А у Документах; усередині — папки учнів «Прізвище Ім'я».
- «Пуск», панель завдань, Провідник: 10 — стрічка, 11 — вкладки й панель команд; дерево, рядок адреси, пошук, вісім виглядів, «Властивості».
- Файли й папки — за правилами Windows: заборонені символи, «(2)» на однакове ім'я, попередження про розширення, Кошик, Shift + Delete, копіювання між C: і D: і переміщення в межах диска, системні папки не видаляються.
- Імітації Блокнота, Фотографій, Word, PowerPoint, Paint, медіапрогравача, Edge.
- Мова схеми своя: УКР / ENG (`WN_KEYS` у `10-model.js`, `wnChar` у `40-input.js`).
- Клавішу Win браузер віддає лише в режимі «На весь екран» через Keyboard Lock (Chrome, Edge); поза ним — кнопка «Win + E».
- Екран — віртуальні 1366×768 (1093×614 з «Крупніше»), масштабується цілком.
- React-вікна й панелі: `src/features/windows/`. `10-model.js` зберігає файлову модель, `20-icons.js` — SVG, `30-view.js` — view-model, `40-input.js` — команди й controller зі зняттям слухачів.

- Токени схем (`--bg`, `--ink`, `--line`… зі значеннями старого сайту) оголошені на `.proj`, а не на `:root`.
- Кожен селектор `keyboard.css` / `win.css` починається з `.kbx` / `.wnx`.
- Глобальні стилі порталу всередині екрана Windows нейтралізовано: у полів вводу — `revert`, у `.btn` — явні значення.
- Нове правило для схеми — теж від її кореня, інакше воно протече в портал (і навпаки: у старому сайті `.ph` Windows фарбував поле клавіатури в чорне).

### Файл для НІТ

На сторінці КТП кнопки «Усі 32 теми», «І семестр · 15 тем», «ІІ семестр · 17 тем» збирають `.xlsx` у браузері (`js/info/nit.js`). Формат — зі шаблону НІТ: аркуш **«План навчання»**, єдиний стовпець A, `A1` — **«Зміст робіт»**, далі по рядку на урок у порядку `n`, дослівно поле `topic` (з «Інструктаж з БЖД.»). Ні дат, ні номерів, ні результатів — НІТ ставить дати сам за розкладом. Ім'я файлу: `Інформатика-4-клас.xlsx` (усі теми), `Інформатика-4-клас-І-семестр.xlsx`, `…-ІІ-семестр.xlsx`.

Змінилися теми — натиснути ще раз і перезавантажити план у НІТ; готові `.xlsx` у репозиторії не зберігаються. Журналу проходження (проведено / дата / нотатки) у порталі немає.
