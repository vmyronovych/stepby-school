# Lessons

## User-supplied course themes

- Show web lesson tasks as separate buttons, with the active task clearly marked.
- Use supplied teaching materials as references; omit source branding and source-site links from course content.
- Let the user supply the course themes when they say they will provide them.
- Adapt only supplied themes. Do not invent a full syllabus before receiving them.
- For beginner web lessons, check source examples against current HTML semantics.

## Ірраціональні рівняння

- Якщо після усунення кореня рівняння лінійне, перенось числа одразу вправо.
- Не зводь лінійне рівняння до вигляду «вираз = 0» без потреби.
- Не показуй ділення на 1 або зведення одного доданка.
- Перевіряй не лише відповідь, а й доцільність кожного навчального кроку.

## Дробові показники степеня

- Розміщуй увесь дріб показника над основним рядком формули.
- Перевіряй положення знаменника: він не має виглядати як частина основи.
- Перевіряй звичайні, дробові та вкладені показники на вузькому екрані.


## Назви навчальних прикладів

- Не показуй номери вправ із підручника в назвах карток і списках вибору.
- Використовуй назви, що описують дію або тип прикладу.


## Повторна перевірка показників у конспекті

- Перевіряй і конспект, і аркуш завдання після змін спільних стилів формул.
- Нижня межа дробового показника має бути вище верхньої межі основи.
- Після зміни стилів додай версію ресурсу, якщо браузер може показувати кешоване оформлення.


## Кеш стилів перед повторним виправленням

- Якщо знімок відрізняється від локального результату, спочатку перевір версію CSS і кеш.
- Не піднімай показники повторно, доки не підтвердиш проблему на актуальних стилях.


## Оформлення математичної теорії

- Для доповнення конспекту використовуй оформлення наявного уроку `rational-power`.
- Розділяй теорію заголовками, а приклади винось в окремі рядки зі спільним рендером формул.

## Читабельність векторних рисунків

- Не використовуй товсту лінію для виділення одного з накладених векторів.
- Використовуй тонкі лінії, виразні вістря та контрастні підписи.
- Перевіряй накладання при k = 1, k > 1 і від’ємному k на широкому й вузькому екранах.

## Формат розв’язання задач із геометрії

- Для задач теми використовуй зошит і спільну оболонку кроків, як в алгебрі 10 класу.
- Показуй одну задачу за раз. Новий крок дописує наступну частину розв’язання. Попередній запис залишається.
- Після останнього кроку дай перехід до наступної задачі.
- Панель дослідження не замінює покрокового розв’язання задач у зошиті.

## Продовження обчислень у рядку

- Не показуй номери вправ і підпунктів у тексті задачі.
- Числові перетворення дописуй через знак рівності в тому самому рядку.
- Анімуй лише нову частину рівності. Уже записані частини залишай видимими.
- На вузькому екрані дозволяй прокрутку формули замість перенесення на новий рядок.

## Позначення кута

- У темі скалярного добутку позначай кут грецькою α.
- Використовуй однакове позначення на рисунку, у формулах і в умовах задач.

## Нові адреси задач і застаріла вкладка

- Після додавання задач оновлюй версію js/data.js разом із версіями інструментів.
- Після зміни маршрутизації оновлюй версію js/app.js.
- Перевіряй повідомлення про неробоче посилання через HTTP, а не лише file://.
- Якщо нова вкладка працює, перевір застарілий стан відкритої сторінки перед зміною маршрутизатора.

## Readable React source

- Format new TSX pages before presenting them for review.
- Put nested JSX, conditional branches, and component props on separate lines when needed.
- Do not compress page markup into long lines to reduce file length.

## Feature structure for React

- Organize feature code under `src/features/<feature>/`.
- Keep pages focused on selecting and composing screens.
- Extract cards, sections, panels, and lifecycle hooks into named feature files.
- Keep generic UI components separate from feature components.
- Pass typed props to extracted components instead of reading global state inside each component.


## Whole-app migration scope

- Inspect generated controls inside engines before defining migration completion.
- A React wrapper around an imperative UI does not finish its component migration.
- Keep math, SVG drawing, physics, and model operations separate from interactive view markup.
- Verify every public route and each interaction family after removing the old bootstrap.


## Вирівнювання дробу в умові

- Об’єднуй обидві частини рівності та знак «=» в одну формулу з вертикальним центруванням.
- Не вставляй окремий дріб після текстового «=»: базова лінія тексту зміщує риску дробу.
- Перевіряй положення риски дробу відносно центру «=» в умовах на широкому й вузькому екранах.


## Проміжок після назви функції

- Відділяй назву тригонометричної функції від аргументу сталим математичним проміжком.
- Перевіряй звичайні аргументи, дроби та квадрат функції в конспекті й зошиті.
