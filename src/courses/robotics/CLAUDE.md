# Робототехніка

Прочитай кореневий [CLAUDE.md](../../../CLAUDE.md). Цей файл — джерело обов’язкових правил курсу; скіли описують процедури, а не замінюють правила.

## Власники файлів

- `lessons/lesson-NN/`: метадані, зміст, унікальний UI, зображення та `.mcar` конкретного заняття. `metadata.ts` — назва й опис картки; `lesson.ts` — зміст. Заняття 8 має власний `MotorLesson.tsx`.
- `shared/`: UI, підготовка, стилі, ілюстрації та збережені документи, які використовуються в кількох заняттях.
- `tools/circuit/`: єдина реалізація електричного кола — двигун, React та CSS. Пресет конкретного заняття живе біля заняття й передається через props.
- `scripts/`: генерація й перевірка; `docs/`: методика, рішення й метадані перевірок; `tests/`: перевірки курсу, `tests/browser/`: браузерні сценарії.
- Заняття не імпортують одне одного. Спільний UI не імпортує файли занять. Послідовність та зв’язки збираються на рівні курсу.
- Не додавай ручні копії в кореневі `assets/`, `css/`, `docs/` чи `tests/`. `publication.cjs` описує публікацію до `dist/assets/robotics/`; збірка зберігає попередні URL `assets/robotics/*` усередині сайту. `dist/` не комітиться.
- Зовнішні імпорти лише через `index.ts` (каталог і посилання), `ui.ts` (екрани), `circuit.ts` (двигун для композиції), `documents.ts` (збережені документи). `publication.cjs` — вхід для збірки, не браузера.

## Навчальний зміст

- 32 послідовні заняття для 3–4 класів. Кожне спирається на попередні знання; нове поняття має підготовку, дослід і перевірку розуміння кожної дитини.
- ESP32 та інструменти Mcar. Шкільні комп’ютери, власні телефони дітей для відповідних занять. Зберігай перевірену послідовність із [прогресії](docs/progression.md).
- На сайті — заняття та інструменти. Не повертай КТП у навігацію робототехніки. Старі документи збережені для сумісності, а не як шаблон нових занять.
- Режими: разом у класі, практика в парі, матеріали вчителя, окрема учнівська сторінка. Учнівська сторінка не відкриває готові розв’язки вчителя.
- Пояснення мають допомагати зрозуміти роботу пристрою. Не додавай службові нотатки про реалізацію чи дублювання схеми словами без навчального призначення.

## Схеми й програми

- Реальні схеми та блоки з Mcar; текстова імітація блоків не замінює зображення програми.
- ESP32 завжди з платою розширення. Додаткові дискретні деталі та моторні драйвери розміщені на mini breadboard; контакти мають відповідати справжнім електричним групам.
- Дроти не перетинаються й не накладаються. Допустиме тільки явне з’єднання на справді спільному контакті; спільний накладений відрізок заборонений. Підписи й розведення мають читатися однозначно.
- Зберігай старт, демонстрацію та розв’язок як окремі файли. Після зміни проєкту онови відповідні зображення та їхні метадані; не підміняй перевірку оновленням хешу без генерації.
- Інструмент «Електричне коло» вбудовується через спільний `CircuitProjector`, без копії двигуна. Особливості інструмента — у [docs/circuit.md](docs/circuit.md).

### Оформлення занять робототехніки

Для всіх занять використовуй затверджений **варіант C — компактний режим показу** та спільний `LessonScreen`. Перед зміною сторінок прочитай [правила оформлення](docs/layout-guidelines.md). Одна компактна шапка, номер перед назвою, зрозумілий вибір матеріалу, основний матеріал у першому екрані. Не повертай окремі великі вступні блоки та дубльовану навігацію. Допоміжний опис і передумови — у «Про заняття». Щільність забезпечуй структурою й відступами, а не дрібним навчальним текстом. Вкладки називай за матеріалом («Дослід», «Підключення», «Програма»), без номерів; кожна показує окремий матеріал. Тематичні назви й запитання розміщуй біля схеми. Не створюй вкладки, що змінюють лише текст при незмінному наборі зображень. Для одного матеріалу вкладок немає. Використовуй спільний `MaterialPanels`, у даних явно пов’язуй пояснення з матеріалом. Зміну спільного правила перевіряй на всіх 32 заняттях, включно з окремою реалізацією заняття 8; перевірки лише заняття 7 недостатньо.

## Процедури для AI

Файли нижче потрібно відкрити явно, коли задача відповідає їхньому призначенню:

- [prepare-lesson](.agents/skills/prepare-lesson/SKILL.md) — створення або зміна навчального заняття.
- [prepare-wiring](.agents/skills/prepare-wiring/SKILL.md) — зміна Mcar-проєктів, схем або зображень блоків.

Для простого переміщення файлів ці процедури не вимагають переробляти навчальний зміст чи перемальовувати незмінені схеми.

## Перевірка

З кореня репозиторію: `npm run build`, `npm run test:robotics`, `npm test`, `npm run test:browser`.
Для Mcar: `node src/courses/robotics/scripts/check.mjs ../mcar` і `node src/courses/robotics/scripts/check-course.mjs ../mcar`. Зовнішній checkout Mcar потрібний для генераторів та цих додаткових перевірок, але не для звичайної збірки чи тестів сайту.

Зміни спільного показу перевіряй на всіх 32 заняттях і чотирьох режимах, на комп’ютері та телефоні. Структурні зміни також мають зберігати старі URL, завантаження файлів, офлайн-показ і роботу інших курсів.
